# Case record: DNS cache poisoning

Assessed against rules R4-R6 of the companion paper's Method section (frame, node/governance partition, evidence per condition). Extracted from the paper's own Demonstration section (Section 6) -- this is the same analysis stated in the manuscript, deposited here as a standalone, citable record.

# DNS cache poisoning: directing External Trust

## Frame
 An organisation's client host j (domain d1) uses a stub resolver designating a recursive resolver r operated by an access provider (d2), which resolves names by following delegations to authoritative servers (d3). The technique class is that disclosed in 2008, in which an off-path attacker induces the resolver to query for non-existent names under a target zone and races forged responses carrying delegation records, so that cache lifetimes offer no protection.

## Operation 1, at r
 *Invariant:* r's cache holds only bindings issued by the zone's authoritative servers. *Operation:* admit and cache a binding not so issued. *Interface:* present, relational, gamma=1 (governance-crossing). The resolver's response admission relation admitted a response matching the question, transaction identifier and destination port, and any node able to forge a source address was a source. *Execution Pathway:* present, local; response processing reaches cache insertion. *Authority:* present, local; the resolver's cache mechanism controls its cache. *Payload:* forged responses. *Delivery:* externally initiated, with the attacker triggering the queries it races. The coordinated 2008 response randomised source ports, which strengthened the admission criterion without removing the relation.

## Operation 2, at j
 *Invariant:* j connects to the address the zone authority issued for a name. *Operation:* j establishes a connection to another address. *Interface:* present, relational, gamma=1 (governance-crossing); the stub admits answers from r. *Execution Pathway:* present, local; from the stub to the connection mechanism. *Authority:* present, local; the connection mechanism's control over its own connection state. *Payload:* the poisoned binding. *Delivery:* automatic on lookup.

## System-of-systems structure
 d1 has designated r, and r follows designations along the delegation chain, so the relation into j is directing External Trust, and r is a Concentration: the entry point for name resolution into every domain that designates it, with fan-out kappa(r) the number of such domains. It is a Cut for name resolution at j unless a second resolver is designated. A node-local assessment of j establishes every instance of Operation 2 and the designation of r. It does not establish Operation 1's admission relation, which is the source-side structure on which the directing relation depends and which is governed in d2. This is the locality implication of Section~(see main text).

## What the case tests
 Name resolution is the directing case most exposed to H4. The mechanism that gives r's answers effect is the connection mechanism, and restricting it to permitted destinations is not specific to r: it constrains destinations however obtained. A narrower ablation exists where the client host enforces egress keyed on resolver provenance, permitting connections only to addresses returned by designated resolvers. Withdrawing r from the designated set then withholds the connecting mechanism's control over connections to addresses r supplied, while r's answers remain admitted and routed. This is classified as an Authority ablation, on the grounds the node-level paper gave for just-in-time privilege: Authority changes by policy while Interface and Execution Pathway are unchanged. The enforcement must be on the client host; placed at a network node, it acts on admission or routing there. The ablation is pre-registered as test A-6 ((see main text)). Where no such enforcement exists, name resolution has no admissible source-specific Authority ablation and is classified as a Concentration carrying a designation. The classification of a directing relation is therefore relative to the assessed configuration, as every assessment in the node-level model is.

## Relocation
 DNSSEC validation requires answers to carry signatures chaining to a configured trust anchor. Forged responses for signed zones fail admission, which denies Operation 1's Interface for that class of source. Where validation is performed at j, the recursive resolver's capacity to select bindings is removed, and the trust now runs to the zone key holders and to the management of the root trust anchor, each independently governed. Operating an internal recursive resolver internalises the recursion role and not the selection of bindings. The case is consistent with H6, and tests it weakly, since the function of resolving names governed by others is external by nature.
